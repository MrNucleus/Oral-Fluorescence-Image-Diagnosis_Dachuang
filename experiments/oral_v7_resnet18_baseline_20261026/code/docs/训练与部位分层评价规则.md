# 整体训练与部位分层评价规则

先用整体训练集训练一个整图二分类模型，用整体验证集选择方案；方案冻结后，使用同一模型、同一阈值及同一份测试预测，分别报告总体和各部位表现。

本规则适用于当前整图二分类训练与后续交接。部位用于评价分层，不是疾病分类，也不要求按三个部位各训练一套模型。默认将已批准队列中的白光、荧光图片作为独立整图样本训练一个模型；这不构成双模态配对融合。另做单模态消融时，须提前固定方案，并仅依据验证集比较。

实际进度、运行证据、失败和交付状态统一追加到[项目工作记录](PROJECT_WORK_LOG.md#pooled-training-site-evaluation)，本文不维护平行进度记录。

## 1. 数据、标签与部位的边界

- 沿用当前版本 `dataset.json` 的 `image_id`、完整图片、标签、模态、来源组和 train/val/test 归属。不要为某个部位重新随机划分，不把验证或测试图片移入训练集。
- `0=normal_candidate`，`1=lesion_candidate`，正类为病变候选。候选标签须保留原有来源和状态，不等于医生确诊、恶性诊断或具体病种。混合、缺失、未知、冲突的证据仍待人工核对；缺标不作为正常，部位文字不产生疾病标签。
- 部位采用当前已发布的匿名部位对应文件及其来源状态，不看照片猜部位，不改登记原文。已知跨组多部位独立列出，不强行指定单一主组；已有明确人工主组确认的记录沿用该确认并保留多部位标记。若某版本仍有缺失或含混部位，也应单列并报告数量。
- 保持来源组不跨集合。同一来源组中的不同模态和图片不拆散。来源文件夹组不等于已确认的患者；真实患者关系尚未核清时，不宣称患者独立评价。
- 将来核实患者关系、图像配对、标签或划分需要更改时，新建版本并重新验证；保留当前冻结版本，不就地修改旧包，也不因测试子组成绩不好而重划分。

## 2. 完整视野和训练集专用操作

- 输入为完整 RGB 图像。保比例缩放并补边；旋转扩展画布后再缩放补边。不得随机裁剪、中心裁剪、裁 XML 框或使用会默认裁图的预训练变换。
- 随机增强仅用于 train；val/test 使用确定性的缩放、补边及标准化。增强视图不增加独立图像或患者数，不能跨集合混入增强池。
- 任何从数据估计的标准化统计、类别权重、重采样比例或校准参数，只能按预定方案从 train/val 的相应允许部分取得，不使用 test。具体而言：标准化统计、损失类别权重和训练采样比例只用 train；阈值与校准方案只用 val 确认。
- 当前代码使用固定 ImageNet 均值/标准差、未加权交叉熵，无类别重采样。不要把类别加权、数据自适应标准化或概率校准写成已实现功能。现行增强参数是待验证的工程起点。

## 3. 验证集选择与方案冻结

当前训练器按最低**整体验证交叉熵**选择 `best.pt` 并早停；AUROC、灵敏度、特异度和平衡准确率用于辅助观察。不要改称按测试集、验证准确率或某个部位的最好成绩选模型。

比较模型或增强方案时，固定相同数据版本、split、模态范围、预处理及训练预算，并事先规定随机种子或重复方案；每次仅改变待比较因素。不同历史数据版本或不一致的标签方向不能直接排列为性能提升。多模态融合若将来开展，须使用确认配对子集，与单模态基线共用该子集及split，另建版本。

当前决策为 `lesion_probability >= 0.5` 判为病变候选，概率方向是 `P(lesion_candidate=1)`。当前未实现阈值搜索。未来若需要调阈值或校准，须先规定目标和方法，只依据整体验证集确认一个全组共用方案，冻结后用于总体、各部位和各模态。不得依据任何测试子组另选阈值。

开始计算最终测试成绩前，保存一份包外的冻结协议，至少包含：

| 字段 | 应记录的内容 |
| --- | --- |
| 数据身份 | 数据版本、`dataset.json` SHA-256、固定 split、类别映射及候选状态 |
| 部位身份 | 匿名 `image_sites.json` SHA-256、分组字段及多部位/缺失处理规则 |
| 模型与输入 | 模型结构、模态范围、输入尺寸、完整视野预处理、初始化方式 |
| 训练与选择 | 代码版本/哈希、训练配置、随机种子、增强策略、选模主指标及早停规则 |
| 冻结权重 | checkpoint 路径、SHA-256、所选 epoch |
| 决策口径 | 正类、概率方向、共同阈值、阈值来源及是否校准 |
| 评价口径 | 总体/部位/模态分层、指标定义、NA规则、置信区间方法及小样本说明 |

训练前的文件完整性、图片可解码性与确定性检查可以读取 test 文件，但不能计算或利用测试成绩选择方案。

## 4. 同一份测试预测与精确联表

1. 冻结后通过独立评估入口生成一次最终测试结果，保存总体 `test_metrics.json` 和逐图 `test_predictions.json`，结果目录位于冻结数据包之外。后续分层统计复用这一份预测。
2. 用 `image_id` 将预测精确连接到同一冻结 `dataset.json` 及匿名部位表，不用文件顺序、截短文件名或模糊匹配。三个文件中的 ID 均须唯一；预测 ID 集合必须与本次预定模态范围内的测试 ID 集合完全一致。
3. 校验部位表与数据清单的对应记录一对一，`split` 和标签一致，预测中的 `label` 与清单一致，测试预测没有 train/val ID。若预测未单列 `split`，以清单核验其确属 test。不能通过静默丢弃或重复行消除不一致。
4. 通过核验后，在同一预测上分别计算总体、各部位及各模态指标；总体保留所有预定测试样本。若将来增加部位×模态交叉分析，提前规定并标明其样本量，不与独立测试集混称。
5. 如联表或来源核验失败，停止发布分层结果，保存问题及修复证据；需要修改冻结输入时另建版本。

## 5. 固定报告口径与小样本解释

总体、各部位、各模态统一采用以下表头，避免只挑成绩较好的组或指标：

| 分层维度 | 组别 | 图片数 n | 正常候选数 | 病变候选数 | 来源组数 | AUROC | 灵敏度 | 特异度 | 平衡准确率 | 准确率 | 混淆矩阵 | 置信区间/限制 |
| --- | --- | ---: | ---: | ---: | ---: | --- | --- | --- | --- | --- | --- | --- |

- 混淆矩阵固定以真实标签为行、预测标签为列，顺序均为 `0,1`。灵敏度针对病变候选，特异度针对正常候选，阈值使用冻结的全组共同值。
- 零样本组的指标标 `NA`；只有单类的组，AUROC和平衡准确率为 `NA`，缺少分母的灵敏度或特异度也为 `NA`，不能用 0 代替。保留可定义的计数和指标，并解释原因。
- 图片数量不能替代独立来源组数量。小样本或少数类别极少的子组只作描述或探索，不据此宣称优劣、临床有效性或稳定泛化；无测试样本的组不能声称已完成效果评价。
- 如计算置信区间，应在冻结协议中预定聚类重采样单位、置信水平、次数及随机种子。同一来源组的图片共同重采样，不能当成相互独立图片；真实患者关系未明时，只能称“按来源组的置信区间”，不能称患者级区间或已解决患者相关性。无法稳定计算时报告 `NA` 或明确未估计及原因，不填造区间。
- 查看测试成绩后再调整模型、阈值、增强、分组或划分，后续成绩标为探索性；若要主张新的独立最终验证，需要另行锁定未参与决策的独立保留集或外部集。不得依据子组测试表现选择参数或重新划分数据。

## 6. 当前代码已支持与尚待实现

当前代码支持整图训练、确定性验证/测试、验证交叉熵选模、固定 0.5 阈值、单独测试入口、冻结数据清单哈希核验及逐图测试预测导出。测试输出的 `image_id`、`label`、`lesion_probability` 可用于后续部位联表。

当前尚未自动完成部位/模态分层汇总、部位表联表校验、阈值搜索、校准、群组置信区间，也未以程序强制测试只能运行一次。上述冻结、联表和报告要求是需执行的评价协议，不是已经实现的功能。数据完整性预检通过也不等于临床标签、整图质量、患者关系或交付验收已全部完成。
