# 在线增强代码使用说明

代码保存在本主项目，可继续编辑和调试。适用于现有 **YOLO 检测框级二分类**，不是整张图像二分类训练器，也不生成五分类标签。实现核对依据为 `github_sources/Oral-Fluorescence-Image-Diagnosis_Dachuang` 的上游提交 `3b6d1d3eb14344bb9fa36729464045203f8308a7`；上游副本用于参考，当前运行入口在本项目 `scripts/`。

所有操作、验证结果及未解决问题统一记录在[项目工作记录](PROJECT_WORK_LOG.md#online-augmentation-code)。方法依据及七项文献见[白光与自体荧光在线增强文献建议](白光与自体荧光在线增强文献建议_2026-10-18.md)。本文是使用指南，不另维护进度记录。

## 修改哪些文件

| 文件 | 用途 |
| --- | --- |
| `src/oral_fluorescence_detection/online_augmentation.py` | 图像/框同步变换、模态识别、数据预检、YOLO Dataset/Trainer 接口 |
| `src/oral_fluorescence_detection/online_yolo.py` | 配置读取、增强约束、训练调用 |
| `configs/online_augmentation.yaml` | 两种模态的增强概率与幅度，日常调参优先改这里 |
| `configs/train_online_yolo.yaml` | 模型、输入大小、批量、设备、轮数等训练参数 |
| `scripts/train_online_yolo.py` | 训练与仅预检入口 |
| `scripts/check_online_augmentation.py` | 数据包校验和、实际加载器、框/类别及验证集稳定性检查 |
| `tests/test_online_augmentation.py` | 合成图像回归测试与一轮合成数据训练测试 |

图片仍从现有数据包读取，在线变换发生在内存中，不另生成增强图片集。图像与标注按 `train/val/test → fluorescence/standard → images/labels` 配对；保留包内 `annotations/`。

## 当前策略

| 配置中的 `profile` | 白光 `standard` | 自体荧光 `fluorescence` |
| --- | --- | --- |
| `baseline` | 确定性缩放/补边 | 确定性缩放/补边 |
| `geometry`，默认 | 水平翻转概率0.5；旋转概率0.5、角度±10° | 同左 |
| `modality` | 几何增强 + 概率0.3的全图共同增益0.90–1.10 | 几何增强；共同增益默认关闭 |

这些范围是待验证的工程起点。荧光共同增益参数预留0.95–1.05，但概率为0；只有开展独立消融时才启用。先比较 `baseline` 与 `geometry`，再比较白光增益；用验证集选择配置，最终配置确定后评估测试集。

旋转扩展画布再补边缩放，保留边缘目标，框随图更新；重叠框保留原有顺序与类别。旋转后的框是包围目标的轴对齐矩形，面积可能增大，画面缩回输入尺寸也可能使小目标变小，仍需临床人员抽查病灶细节。

共同增益对三通道使用同一乘数；若会产生新的255截断，本次增益跳过。它保留数值比例的条件包括无截断且忽略整数舍入，不代表JPEG像素经过光学定量标定。关闭色相/饱和度抖动、Mosaic、MixUp、CutMix、随机擦除、随机裁切、模糊及噪声。自定义训练管线替换框架默认管线，也阻止其自动插入的 Albumentations 操作。验证/测试只缩放与补边，关闭随机增强和TTA。

## 安装和预检

在主项目根目录，用训练环境的 Python 执行：

```bash
python -m pip install -e '.[train,dev]'
python scripts/train_online_yolo.py \
  --data 'data/processed/01_当前工作包/oral_binary_v5_yolo_2026-10-18_v1/dataset.yaml' \
  --check-only
```

`ultralytics==8.4.182` 已固定在 `pyproject.toml`。自定义接口依赖此版本，升级后需重新核对和测试；PyTorch/CUDA版本由训练同学按服务器选择。仅预检不会加载模型权重或执行训练。

现有三份数据入口可分别训练：`dataset.yaml` 包含两种模态，`dataset_standard.yaml` 仅白光，`dataset_fluorescence.yaml` 仅荧光。两模态图片在这里作为独立样本；这不是配准的白光/荧光双输入融合模型。

不要运行上游旧 `prepare_data.py` 来重建当前包：上游旧映射为 `l=0,n=1`、划分比例70/15/15，缺标注可作背景；当前v5为 **`n=0 / normal_region`、`l=1 / lesion_region`**，沿用冻结的约80/10/10来源文件夹组划分。`n` 是已标出的正常区域，不是“缺标注”。类别表示区域标注，不等同组织病理确诊。

预检核对图片清单、模态路径、逐图框数、YOLO坐标范围、类名及来源文件夹组跨集情况，并拒绝缺失/空标签、可触发自动修复的JPEG及旁置`.npy`缓存。它不重新认定患者关系；来源文件夹组不跨集不等于已经完成真实患者身份关联审计。

## 检查代码与真实加载器

```bash
python -m pytest tests/test_online_augmentation.py -q
python scripts/check_online_augmentation.py \
  --data 'data/processed/01_当前工作包/oral_binary_v5_yolo_2026-10-18_v1/dataset.yaml' \
  --all
```

第一条使用合成图片测试几何对齐、增益、泄漏拦截、框类别和一轮CPU训练，不训练临床图像。第二条在640输入大小下加载全部现有图片，核对类别顺序、框数、变换后坐标、验证/测试确定性；前后复核包内校验和及文件清单。只作结构验收，不用测试集调参，也不输出临床照片预览。

报告和标签缓存保存在 `outputs/`，不写进冻结数据包。检查脚本的 `--output` 必须是数据包外的新目录，默认自动创建带时间戳的目录；不加 `--all` 时每个split每种模态抽2张做快速加载检查，输入清单和包内校验和仍完整检查。

本机验证时使用的隔离依赖在 `outputs/online_augmentation_validation_2026-10-19/augmentation-runtime/`，未覆盖现有Conda环境。尚未正常安装依赖时，可临时这样运行（正式服务器使用上面的安装方式）：

```bash
YOLO_OFFLINE=true YOLO_AUTOINSTALL=false NO_ALBUMENTATIONS_UPDATE=1 \
YOLO_CONFIG_DIR="$PWD/outputs/online_augmentation_validation_2026-10-19/augmentation-settings" \
PYTHONPATH="$PWD/outputs/online_augmentation_validation_2026-10-19/augmentation-runtime" \
/opt/anaconda3/envs/oral-fluorescence/bin/python scripts/train_online_yolo.py \
  --data 'data/processed/01_当前工作包/oral_binary_v5_yolo_2026-10-18_v1/dataset.yaml' \
  --check-only
```

## 正式训练和交接

在有CUDA GPU的服务器上，先完成预检，再由训练同学执行，例如：

```bash
python scripts/train_online_yolo.py \
  --data '/实际数据包位置/dataset_standard.yaml' \
  --profile modality --device 0 --name standard_modality_seed42
python scripts/train_online_yolo.py \
  --data '/实际数据包位置/dataset_fluorescence.yaml' \
  --profile geometry --device 0 --name fluorescence_geometry_seed42
```

配置默认 `device: 0`，Mac调试时显式使用 `--device mps` 或 `--device cpu`，并减少轮数/批量。标准训练可能自动下载指定的预训练权重；离线服务器应先准备本地权重并用 `--model /权重路径/best.pt` 指定，架构和类别兼容性由训练同学检查。本轮代码仅验证单设备训练，未开放DDP或`resume`恢复接口。

每次训练在 `outputs/online_yolo_runs/<实验名>/` 留下框架 `args.yaml`、指标、权重及 `oral_augmentation.json`。后者记录增强参数、随机种子、依赖版本、模块哈希和输入预检；这是运行配置记录，不是每张图每次随机抽样的完整流水。相同实验名自动生成新目录。固定种子不保证不同硬件/库版本逐位相同。

交接可复制本项目代码骨架：`pyproject.toml`、上表文件和 `src/oral_fluorescence_detection/__init__.py`，附本说明与文献建议。训练数据另拷贝完整v5 YOLO包，保留 `image_level/`、三份数据YAML、模态目录、标注和 `CHECKSUMS.sha256`；源对应表、登记表等私密材料只交给获授权人员。`github_sources`、隔离验证依赖和缓存无需交给训练同学，也无需复制到GitHub。

后续数据更改应先发布新版本、更新清单/框标注和冻结划分，再将 `--data` 指向新版本并重新预检；在线增强不需要提前重做一批增强图片。每次调试改动都在[统一工作记录](PROJECT_WORK_LOG.md)追加日期、参数和结果，临床逐图记录继续留在忽略的私密目录。
